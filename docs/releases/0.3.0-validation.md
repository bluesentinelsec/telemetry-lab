# 0.3.0 release validation

Validation ran on September 22–23, 2026, after Windows Rust PR #63 was merged. Every shipped program/configuration combination was exercised on disposable Debian 13 and Windows Server 2025 hosts. This is a one-iteration release smoke test, not the dissertation's repeated experiment. **The qualified expanded suites passed; two retained Linux pilot programs were collector-invalid in this original run despite successful execution and expected alerts. The follow-up below identifies and fixes their collector defect.**

## Scope and results

| Suite | Linux | Windows | Result |
|---|---:|---:|---|
| Primitives | 13 × 8 = 104 | 3 × 6 = 18 | All 122 valid; tmon collection and tap analysis completed |
| Expanded active composites | 30 × 8 = 240 | 24 × 8 = 192 | Linux: 238 alerts, two valid misses. Windows: 184 alerts, eight unqualified onion diagnostics |
| Same-binary controls | 240 | 192 | All controls clean in valid attempts |
| Negative baselines | 8 | — | All clean in valid attempts |
| Retained legacy pilots | 7 × 8 = 56 | 4 × 6 = 24 | All exit 0; two Linux pilots retain strict collector-health failures |

This accounts for **634 primary executions and 440 controls/baselines**, before rechecks and diagnostic investigations. Windows Rust primitives and legacy pilots are not shipped; the release does not imply their implementation. The combined analysis of 122 primitive traces produced 42 figures and retained both host inventories.

Linux used Falco 0.45.0 (libs 0.26.0), modern eBPF, kernel 6.12.107+deb13-cloud-amd64, and the pinned 95-rule supplied snapshot (81 stock-enabled rules, 30 selected targets). All 30 selected rules were demonstrated. The Go cgo and static `reverse_shell` executions passed behavior and collection checks without the target alert. These valid misses were retained without changing programs or rules.

Windows used Sysmon 15.22 and Hayabusa 4.1.0, with 4,987 supplied rules and 2,269 enabled Sysmon rules. All 23 qualified targets alerted across eight configurations: **184 active alerts and 184 clean controls**. The eight `dns_onion` active executions failed normal resolver resolution; their eight controls passed. These diagnostic cases are excluded from the qualified rule count.

Legacy programs lack the expanded suite's independent behavior contracts. Exit success and observed alerts are operational evidence, not qualification. In particular, the Windows legacy IMDS cases had no attributed alert or network event, so this report does not claim they are qualified detection tests.

## Failures, fixes, and retained limitations

- Eighteen initial Windows primitive attempts were falsely rejected because Windows PowerShell 5.1 returned a null `Start-Process` exit code. The runner now owns the process handle and drains stdout/stderr asynchronously. All 18 reruns passed with zero lost telemetry. A CI regression test also rejects nonzero monitor exits and lost events.
- One C/MSVCRT DNS attempt contained a delayed Sysmon DNS record carrying an old process GUID. The analyzer now marks delayed DNS/network records with conflicting attribution as incomplete unless a later process creation proves legitimate PID reuse. It never substitutes PID-only attribution for a positive alert. The unchanged program/rule recheck produced the exact target alert and a clean control.
- Twelve of 488 initial Linux expanded executions failed the strict collector gate. All twelve separately recorded rechecks passed. No valid detection miss was rerun to seek an alert.
- Four of 56 initial Linux legacy attempts failed collector health. Two passed rechecks. `linux-c-musl/read_sensitive_file` and `linux-c-musl/clear_log` repeatedly incremented the entry-pairing retrieval counter by one, while kernel-drop counters stayed unchanged. Both exit 0 and produce their expected attributed alerts. Fresh-collector, affinity, and state-repair diagnostics did not resolve the condition. Those original attempts remain **collector-invalid**, tracked in [issue #65](https://github.com/bluesentinelsec/telemetry-lab/issues/65). The follow-up below resolves the cause; no gate was relaxed to call an invalid attempt valid.

All original attempts, rechecks, and diagnostics are retained. The two pilot limitations and onion diagnostics are not evidence of validated runtime-induced detection misses.

## Release integrity and evidence

Release assembly requires the complete shipped roster and verifies Windows executable/dependency build hashes. It includes Linux detector setup files, excludes macOS archive metadata, and records every bundled file's SHA-256. Inventory generation now records the tested bundle and the Falco engine version rather than its driver version. The release workflow preserves an already-published tested release.

The release assets reuse the exact native executable/library bytes exercised in the lab. `component-lock.json` records the eight component workflow runs, their source commits, relevant source equivalence checks, and 1,763 artifact-file hashes. A separate lock covers 903 packaged native executables/libraries; final packaging must match it. Support/analyzer fixes are packaged from the release commit. No test program or detection rule was modified for this validation.

Raw JSONL, EVTX, Falco records, health snapshots, manifests, analysis, SSM logs, and failed attempts are privately archived under `release-0.3.0-2026-09-22`. Host archives are checksummed and their file inventories verified before lab teardown. Public release assets include `validation-summary.json`, `component-lock.json`, and `SHA256SUMS` alongside both OS bundles.

## Collector follow-up (publication deferred)

A fresh Debian lab reproduced both C/musl failures with packaged Falco 0.45.0 and a source build of the same upstream version. At syscall entry, eBPF could not read a pathname on a not-yet-faulted-in memory page, while flags remained present. By exit the pathname was readable. libsinsp incorrectly discarded the partial entry and then reported a missing pair. A cold/warm pathname-mapping diagnostic reproduced and isolated this condition.

[PR #66](https://github.com/bluesentinelsec/telemetry-lab/pull/66) supplies a [pinned parser patch and regression tests](../../ttp-composite/linux/coverage/falco-health-fix/README.md). It retains partially populated entries for pairing; the existing exit parser supplies the pathname fallback. The original TTP binaries, supplied rules, and strict health gate are unchanged. The patched detector is explicitly labeled `0.45.0+telemetry-lab.1` and recorded by hash and build receipt. It is a lab-maintained build, not an upstream release.

Both original program hashes pass with the fix and still produce their expected alerts, including five further repetitions of each case (10/10 valid). The cold/warm diagnostic records no retrieval drops after the fix, while its cold entry pathname remains unreadable. Four parser tests pass, including genuinely missing-entry failure and entry-pathname precedence; the two partial-entry tests fail on unpatched code. Detailed follow-up evidence is archived privately under `falco-health-2026-09-22`.

Publication remains deferred. The existing draft assets predate this follow-up and must be reassembled and verified before any later publication; this report does not reclassify or replace the original failed attempts.
